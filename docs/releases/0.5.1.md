# Vult 0.5.1

Vult 0.5.1 gives Vult on your computer a short, fixed address and makes first
setup clearer for any agent.

- **Vult opens at `https://vult.localhost`.** Each computer keeps its own port,
  for example `https://vult.localhost:53877`, instead of a long random address.
  The name is still Vult's own, so other local web apps never share its
  sign-in or passkeys.
- **Simpler local agent setup.** Local setup no longer asks you to pick Claude
  Code or Codex. One command adds Vult to the agents it finds.
- **Clearer first steps.** Shorter copy for adding your first statement and
  connecting your agent.
- **Recovery codes fit.** Each code is shown in full on its own line.
- **Choices show focus clearly.** Choosing Business or Personal with the
  keyboard highlights the whole choice.
- **Vult tells you when it can update.** While open on a Mac, Vult checks for a
  newer release at most every 12 hours and shows a small notice in the sidebar.
  Run `vult update`, or ask your agent to: it downloads and verifies the installer
  for the exact release it checked, then backs up every Book before installing.
  `vult update --check` only reports whether one is available. The check reads
  only the public release manifest and sends nothing about your installation.
- **A new Vult on a server opens in the first-run scene.** It starts at your
  first Book, like a local install, in the theme you were already using.
- **A new first screen for your passkey.** Setup on a Mac opens on "Secure
  your Vult", the same passkey screen as Vult's hosted sign-up. A failed attempt
  says so under the button and never asks for a setup code. Choosing an
  authenticator app opens its own setup screen, and recovery codes are shown
  the same way as on the hosted sign-up.
- **Sign-in pages match the first-run scene.** They share its top bar, with a
  quiet logo and a Light, Dark or System theme menu that remembers your choice.
- **"Timezone".** Book setup and Settings say Timezone instead of Accounting
  timezone.

## Upgrade

From 0.5.0, upgrade with the same command you installed with. Later releases
can use `vult update`.

```sh
curl -fsSL https://vult.sh | sh
```

Your Books, entries, sources, connections and keys stay as they are. Because a
passkey belongs to the address it was made at, run `vult open` after upgrading
from 0.5.0 or earlier: macOS asks you to approve Vult's new address once, then
Vult asks you to create a passkey for it and shows new recovery codes. Your old
passkey and recovery codes stop working, and agents connected on this computer
ask to be let in again.

0.5.1 adds no database migration.
