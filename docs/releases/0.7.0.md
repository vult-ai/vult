# Vult 0.7.0

Vult 0.7.0 makes upgrades safer and adds recovery points, and it carries the
groundwork for signed updates from inside the app.

- **Safer upgrades.** Starting Vult no longer changes the database. The
  installer updates it in a separate step while Vult is stopped, in one
  transaction that is rolled back if any recorded fact (Books, accounts,
  entries, lines or attached documents) would change. If Vult finds a database
  from an earlier version, it says so and doesn't start, rather than updating
  it on the way in.
- **Recovery points on a Mac.** `sudo vult recovery-point` stops Vult briefly
  and saves an instant copy of its data and an archive of every Book encrypted
  with your recovery key, and reads both back before it reports success.
  `sudo vult restore --recovery-point books.age` restores that archive onto a
  newly installed Vult, on this Mac or another, with your recovery key and no
  sign-in. See [Back up, export and restore](../user/backup-and-restore.md).
- **Update from the app on a Mac.** When a newer release is available, the
  sidebar shows an **Update** button. It installs only a release two
  independent signatures agree on: the release signature, and a rebuild from
  the public source that produced the identical program. It keeps a copy of
  your data and puts the previous version back if anything fails;
  `sudo vult update undo` goes back afterwards. Releases after 0.7.0 can be
  installed this way; 0.7.0 itself is installed as before.
- **Reproducible builds.** The program an update installs, the bundled
  PostgreSQL and the Linux images build byte for byte the same on a clean
  machine, so anyone can check a release matches its source.

## Upgrade

Run `vult update`, or the command you installed with:

```sh
curl -fsSL https://vult.sh | sh
```

Your Books, entries, sources, connections and sign-in stay as they are. 0.7.0
adds no database migration. The installer now runs the database step itself
before starting Vult; a Vult started by hand on an older database asks for
that step instead of changing the database.
